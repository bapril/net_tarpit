# net_tarpit

A standalone HTTP tarpit. It answers each request with a believable payload and a matching `Content-Length`. Then it keeps the connection open and trickles ASCII text at a low, fixed rate until the client gives up.

It is meant to slow down scanners and crawlers that hit a port or path you do not want them on. Run it only on systems you own or are authorized to defend.

## How it works

1. A client connects and sends an HTTP request.
2. The tool picks a content type: the URL extension first, then the `Accept` header, then HTML.
3. It generates a small valid payload of that type and sends headers with `Content-Length` equal to the payload size.
4. After the payload, it keeps sending printable ASCII: `-run` copies of each character from `0x20` to `0x7E` in turn, then it repeats. The default is 10000 copies.
5. Everything, including the headers, is sent at the rate set by `-rate`. The default is 2000 bits per second.
6. The session ends when the client disconnects.

Each connection runs in its own goroutine, so many sessions run at once.

Supported types:

| Extension | Content-Type |
|---|---|
| `.html`, `.htm` | `text/html` |
| `.json` | `application/json` |
| `.xml` | `application/xml` (`text/xml` if the client asks for it) |
| `.csv` | `text/csv` |
| `.txt` | `text/plain` |
| `.png` | `image/png` |
| `.pdf` | `application/pdf` |
| `.zip` | `application/zip` |

## Setup

You need Go 1.21 or later.

```
go build -o tarpit .
go test ./...
```

## Usage

```
./tarpit -listen :8080 -rate 2000 -run 10000
```

| Flag | Default | Meaning |
|---|---|---|
| `-listen` | `:8080` | Address and port to listen on |
| `-rate` | `2000` | Send rate in bits per second (minimum 8). The `TARPIT_RATE` environment variable sets the default. |
| `-run` | `10000` | Copies of each ASCII character sent in turn after the payload |

Ports below 1024 need extra privileges. Use a high port and redirect traffic to it if you can.

## Trying it

`curl` stops reading at `Content-Length`, so it will not show the stream after the payload. To see the stream, read the raw socket:

```
printf 'GET /x.json HTTP/1.1\r\nHost: x\r\n\r\n' | nc 127.0.0.1 8080
```

You will see the headers, the 57-byte JSON body, then a continuing stream of ASCII text. Press Ctrl-C to stop.

A request must end with a blank line. If you type the request line by hand in `nc`, press Enter twice. A request that is not complete within 10 seconds is dropped.

## Logging

Logs go to standard error. Every line for a session starts with a random UUID in brackets.

```
[6ef93741-...] 127.0.0.1:59327 request GET /a.json -> application/json payload=57B
[6ef93741-...] 127.0.0.1:59327 sent 1 MiB
[6ef93741-...] 127.0.0.1:59327 session ended after 1.052s, 10000 bytes sent: write tcp ...: broken pipe
```

- A line is written when a request arrives and when the session ends.
- A `sent N MiB` line is written when a session's total reaches 1, 2, 4, 8, 16 MiB and so on. The total includes the headers. At 2 Kbps the first line takes about 70 minutes.
- Requests that cannot be parsed are logged as `bad request`.
- The end line appears when the next write fails, so it can be late if a client vanishes without closing the connection.

## Deployment notes

- **Run it standalone.** Apache, nginx and other HTTP proxies enforce `Content-Length` and will cut off the bytes after the payload. Do not put an HTTP proxy in front of it.
- **nginx `stream` module.** A TCP passthrough should keep the extra bytes, because it does not parse HTTP. This has not been tested.

  ```
  stream {
      server {
          listen 80;
          proxy_pass 127.0.0.1:8080;
      }
  }
  ```

- **No TLS.** An `https://` client gets no reply and is dropped after 10 seconds.

## Limits

- There is no cap on concurrent connections and no idle timeout. A flood of connections can exhaust file descriptors. Set `ulimit -n` and use a firewall or connection limits for exposed hosts.
- The PDF payload has no xref table. Viewers repair it, but strict parsers may reject it.
- Only JSON and PNG have been tested against a live server. The other types are generated by the same code path, but they have not been checked individually.
